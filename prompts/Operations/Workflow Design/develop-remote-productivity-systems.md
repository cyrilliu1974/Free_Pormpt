# Remote Productivity System Design Prompt

## 簡介

The Remote Productivity System Design Prompt is a free AI prompt that creates a scalable, outcome-focused framework for tracking remote team performance across any team size. This remote productivity prompt for ChatGPT, Claude, Gemini, and Grok produces an eight-part system covering quantitative and qualitative metrics, tool categories for project management and time insights, communication protocols for async and synchronous work, goal-setting frameworks like OKRs, staged performance review cycles, and phased implementation roadmaps spanning 3-6 months. Instead of surveillance-focused approaches, it emphasizes autonomy, trust, and sustainable improvement - ideal for management consultants, team leads, and HR professionals designing systems that balance accountability with flexibility across distributed workforces. ● Identifies five key productivity metrics tailored to your team size, balancing output-based and impact-based indicators ● Recommends tool categories by function rather than specific products, ensuring the system remains vendor-neutral and adaptable ● Outlines communication cadences, async protocols, and documentation practices that maintain visibility without micromanagement ● Provides a complete performance review process with preparation stages, evaluation criteria, and feedback delivery methods ● Includes mitigation strategies for common remote work challenges like timezone conflicts, isolation, and metric gaming ● Delivers a phased implementation roadmap with milestones that build from foundational elements to full system maturity ## Prompt

```
## Role
You are a management consultant specializing in remote work productivity systems. Design a comprehensive, scalable framework for tracking and measuring productivity that adapts to team dynamics and emphasizes outcomes over surveillance.

## Task
Create a detailed productivity tracking system for a remote team of {{team-size}}. The system should be practical, customizable, and focused on sustainable performance improvement rather than micromanagement.

## Context
Remote teams require different measurement approaches than co-located teams. Effective systems balance accountability with autonomy, use multiple data sources to avoid gaming metrics, and align individual work with team objectives. The framework must scale as the team grows and accommodate different work styles.

## Output
Provide a structured system design covering:

**Productivity Metrics**
Identify 5 key metrics appropriate for the team size, explaining what each measures and why it matters. Include both quantitative (output-based) and qualitative (impact-based) indicators.

**Tracking Tools & Technologies**
Recommend 4 categories of tools by functionality (project management, time insights, communication analytics, goal tracking) with the key features needed rather than specific products.

**Communication & Collaboration Framework**
Outline strategies for maintaining visibility and connection: meeting cadences, async communication protocols, documentation practices, and informal touchpoints.

**Goal Setting & Alignment**
Describe how to cascade objectives from company to team to individual level, including OKR or similar frameworks, check-in frequency, and alignment mechanisms.

**Performance Review Process**
Detail a review cycle with clear stages: preparation, data gathering, evaluation criteria, feedback delivery, and development planning. Specify review frequency appropriate to {{team-size}}.

**Best Practices**
List 5 actionable practices for sustaining productivity: trust-building, boundary setting, recognition systems, skill development, and avoiding burnout.

**Potential Challenges & Solutions**
Identify 3 common obstacles (timezone differences, isolation, metric gaming, etc.) with specific mitigation strategies for each.

**Implementation Roadmap**
Provide a phased rollout plan with milestones, starting with foundational elements and building toward full system maturity over 3-6 months.
```
